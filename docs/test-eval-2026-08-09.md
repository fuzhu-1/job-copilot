## 四、本次测试周期发现并已修复的 Bug

1. **匹配页一直"匹配中"**：SSE 流用同一 SQLAlchemy 会话反复读取任务，身份映射返回缓存旧快照，完成事件永远读不到。修复：轮询前 db.refresh（提交 f416173）。
2. **任务完成但状态仍为 running**：成功路径未写状态。修复：完成后落库 completed（f416173）。
3. **前端把连接中断误判为任务失败**：EventSource 的 error 事件同时承载任务错误与传输错误。修复：区分 data 有无，传输错误自动重连并限次（f416173）。
4. **简历解析 JSON 截断失败**：推理模型 max_tokens 不足。修复：默认上限提到 4000、简历 6000、无效输出最多重试 3 次（c8f7f36）。
5. **模型配置错误导致 LLM 全功能异常**：.env 中 deepseek-chat 在 Key 上不存在。修复：改为 deepseek-v4-flash，一键脚本自动校验/修正模型名。
6. **匹配偶发全零分**：全零重试由 1 次加强为最多 3 次，golden 区间按实测校准。

## 五、遗留小事项（不影响使用）

- JD URL 录入依赖页面内容：example.com 这类非招聘页能抓取成功，但结构化提取不出岗位信息属正常降级；真实招聘页可正常提取。
- 数据库中存在本会话测试期间产生的历史 JD（含早期空字段测试记录），可在「岗位 JD」页批量删除；正式使用建议清一遍。
- v4 推理模型单次 LLM 调用约 10~40 秒，匹配多岗位时总耗时 = 岗位数 × 单次耗时，属模型特性而非卡死。
- 面试评分（STAR）由模型给分，个别回答可能偏低，仅供参考，不阻塞流程。
